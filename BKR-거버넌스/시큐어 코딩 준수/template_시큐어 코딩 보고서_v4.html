▌ 7대 분석 카테고리
카테고리 정의 주요 대상 예시
Security
보안 취약점		 인증·인가 우회, SQL 인젝션, 암호화 결함, XSS, 파일 업로드 취약점 등 직접적 보안 결함. 가장 높은 우선순위로 처리 필요. JwtFilter, SecurityConfig, SQL Mapper, 암호화 유틸
Reliability
신뢰성 결함		 NullPointerException, 자원 누수(Connection/Stream 미닫힘), 예외 처리 미흡, 동시성 문제 등 런타임 오류를 유발하는 결함. Service, DAO, Filter, try-catch 블록
Maintainability
유지보수성(Code Smell)		 높은 인지복잡도, 과도하게 긴 메서드, 리터럴 오용 등 코드 품질 문제. 보안 결함은 아니나 유지보수를 어렵게 하여 간접적 위험 증가. 복잡 메서드, 중복 블록, TODO 잔여 주석
Security Hotspots
보안 검토 필요 지점		 취약점으로 확정되지 않았으나 반드시 사람이 검토해야 할 지점. "취약하다"가 아닌 "이 지점은 반드시 검토하세요"의 의미. HIGH / MEDIUM / LOW 등급 사용. 암호화 알고리즘 선택, 외부 URL 호출, 권한 검사 로직
Accepted Issues
인지된 위험/허용 항목		 의도적으로 허용한 위험, 레거시 호환 불가 항목, 기술부채로 관리 중인 항목. WONT_FIX / TECHNICAL_DEBT / FALSE_POSITIVE 로 분류하며 반드시 허용 근거와 재검토 시점을 문서화해야 함. CSRF disable (JWT 전용), 레거시 MD5 (마이그레이션 예정)
Coverage
테스트 커버리지 부재		 보안 로직·인증·인가·입력 검증 메서드에 단위 테스트가 없는 영역. 보안 패치 후 회귀 검증이 불가능한 상태를 나타냄. JwtFilter, Passwdcrypt, FileService 검증 로직
Duplications
코드 중복		 동일·유사 코드 블록이 여러 위치에 존재. 특히 보안 검증 로직 중복 시 패치 누락 위험이 높음 (한 곳만 수정 시 다른 곳에 취약점 잔존). 로그인 검증, IP 접근 제어, JWT 파싱 로직 중복
▌ 심각도(Severity) 등급 — 공통 기준
등급 대응 기한 의미 및 기준 대표 예시
BLOCKER 즉시 / 배포 중단 악용 시 시스템 전체가 위협받는 수준. 발견 즉시 배포 중단 및 긴급 수정 필요. 인증 완전 우회, 원격 코드 실행, DB 전체 노출
CRITICAL 24시간 이내 인증·인가·민감정보에 직접 영향을 주는 심각한 결함. 즉시 수정하지 않으면 데이터 침해 발생 가능. SQL Injection, 하드코딩 자격증명, 취약 암호화
MAJOR 7일 이내 조건부 악용 가능하거나 중요 데이터에 위협이 되는 결함. 단기 내 반드시 수정 필요. CORS 과다 허용, CSRF 미적용, XSS 가능, 자원 누수
MINOR 30일 이내 방어 심층화 미흡 또는 잠재적 오작동 가능성. 단독 악용은 어려우나 중기 내 개선 필요. 민감정보 로그 기록, 보안 헤더 누락
INFO 90일 이내 보안·품질 모범사례 미준수 수준. 장기 개선 과제로 관리. 디버그 로그 잔존, 보안 주석 누락
HIGH / MEDIUM / LOW Hotspots 전용 Security Hotspots 전용 등급. 취약 여부 미확정, 사람이 직접 검토 후 FIXED / SAFE / BLOCKER~INFO로 상태 전환 필요. 암호화 알고리즘 선택, 외부 URL 호출, 권한 검사
WONT_FIX
TECH_DEBT		 Accepted 전용 Accepted Issues 전용 분류. 의도적 허용(WONT_FIX) 또는 기술부채 계획(TECHNICAL_DEBT). 반드시 근거 주석 및 재검토 일자 명시. CSRF disable(JWT 전용), 레거시 MD5 유지
※ BLOCKER + CRITICAL = 즉시 수정 대상  |  Security Hotspots는 취약점 확정 전 검토 단계이므로 별도 심각도(HIGH/MEDIUM/LOW) 적용  |  Accepted Issues는 허용 근거 문서화가 완료된 경우에만 해당 분류 사용
